# ADR-0004：声明式计价规则格式

- 状态：已接受
- 日期：2026-11-17
- 关联：AGENTS.md §6.4；ROADMAP P3（PRICE-001/002）

## 背景

计费规则需要“完全可配置”以适配不同专线企业的报价方式，但直接执行客户/运营编写的代码或脚本会带来严重的安全与正确性风险。

## 决策

1. 计费规则完全声明式：只允许白名单字段、操作符和计算策略；禁止执行任意 C#、SQL、JavaScript、表达式树或动态脚本。
2. 第一版规则能力：按重量/体积/件数/票数计费、重量与体积取大取小或指定策略、起步价与最低收费与固定费用、分段计费与超出部分计费、线路/始发/目的网点条件、客户专属规则与默认规则、提货/送货/装卸/包装等附加费、折扣优惠、金额精度与舍入方式和规则优先级。
3. 规则生命周期：草稿 → 结构校验 → 语义校验 → 试算 → 发布 → （停用）；已发布版本不可原地修改，修改生成新版本。
4. 计价结果保存规则版本、输入快照和费用明细，保证历史运单可解释、可复现；规则变更不影响历史运单。
5. 规则匹配失败必须明确报错，不得静默按零元计费；重新计价必须是显式业务操作，保留前后结果和操作记录。
6. 金额计算一律 `decimal`（PostgreSQL `NUMERIC(18,2)` 或经设计确认的精度）。

## 后果

- 规则模型与计算引擎需要大量单元测试覆盖：边界值、舍入、分段、组合规则。
- 计价结果必须能解释每项费用的来源（试算与明细解释是验收标准）。

## 依据

AGENTS.md §6.4（计费规则）；ROADMAP P3（规则能力清单、安全与一致性要求、验收标准）。
