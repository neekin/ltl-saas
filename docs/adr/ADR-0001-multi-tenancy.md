# ADR-0001：多租户隔离策略

- 状态：已接受
- 日期：2026-11-17
- 关联：AGENTS.md §5；ROADMAP P1（TEN-001、ORG-001/002）

## 背景

本系统是面向多家专线物流企业的多租户 SaaS。租户业务数据（运单、客户、财务、COD 等）如果隔离不当，会造成跨租户数据泄露，属于不可接受的安全事故。

## 决策

1. 一家企业对应一个 Tenant；一个租户下有多个直营网点（Branch）。
2. 所有租户业务数据表必须带 `tenant_id`；`tenant_id` 只能从已验证身份和服务端租户上下文解析，不信任客户端在 Body/Query/Header 中自行提交的租户 ID。
3. 租户范围检查覆盖查询、更新、删除、导出、文件访问和后台任务。
4. 跨租户关联通过复合外键或等效数据库约束保证一致性；租户范围唯一约束必须包含 `tenant_id`。
5. EF Core 全局查询过滤器作为纵深防御，不是唯一安全边界；原生 SQL 必须显式加入租户范围条件。
6. 网点数据范围与角色权限分开建模；当前网点选择器只改变工作上下文，不代表自动获得该网点权限；不得只靠前端隐藏菜单/按钮实现授权。

## 后果

- 每个涉及数据访问的功能必须按 AGENTS.md §5.3 补充越权测试（跨租户读/写、ID 猜测、导出、后台任务等）。
- 后台任务（Hangfire）必须显式建立租户上下文；连接池复用不得泄漏租户上下文。

## 依据

AGENTS.md §1（业务约束）、§5（多租户与网点权限）；ROADMAP P1 验收标准（租户 A 无法读取或修改租户 B 的任何业务数据）。
