# ADR-0007：计价规则版本按规则集粒度，定义以 JSONB 快照存储

- 状态：已接受
- 日期：2026-11-17
- 关联：AGENTS.md §6.4；ADR-0004（声明式计价）；docs/requirements/PRICE-001.md

## 背景

已发布计价规则必须版本化且不可原地修改（AGENTS §6.4）。需要决定：版本以什么粒度组织；规则定义以何种形式存储。

## 决策

1. **版本粒度 = 规则集**。一次发布固化整套规则（条件、费用项、优先级、策略）为不可变快照。跨规则约束（优先级唯一、边界覆盖、无歧义匹配）只能对整套定义进行校验，逐条规则版本化会产生从未整体校验过的版本组合。
2. **定义存储 = 版本行内 JSONB 快照**。权威结构是强类型 C# 模型（枚举白名单 + 分类型费用项），经结构校验（反序列化拒绝未知成员/枚举/多态类型）与语义校验（纯函数校验器）后写入。执行器（PRICE-002）按快照计算，同输入同版本结果确定可复现。
3. **生命周期**：Draft → Published（不可变）→ Superseded；每规则集同时最多一个 Draft、一个 Published（PostgreSQL 部分唯一索引强制）；停用匹配 = 停用规则集；版本历史永不删除。
4. **历史快照不建跨模块外键**：条件中引用的线路/网点/客户资源在执行器运行时按租户范围实时解析校验，不将资源生命周期与历史版本耦合。

## 后果

- 规则变更审查以整套版本为单位，试算解释可引用版本快照原文；
- JSONB 内数值不受关系列精度约束，精度边界由 C# 模型与校验器保证（金额 decimal，金额 2 位、单价 4 位舍入策略白名单化）；
- 部分唯一索引保证"当前生效版本"唯一性在数据库层成立，发布事务内完成新旧版本状态迁移。

## 依据

AGENTS §6.4（版本不可原地修改、保存规则版本与输入快照、禁止任意代码）；ROADMAP P3（版本历史、可解释、确定可复现）。
