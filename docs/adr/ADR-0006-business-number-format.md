# ADR-0006：业务单号格式与序号分配机制

- 状态：已接受（格式为建议值，集中封装可单点变更）
- 日期：2026-11-17
- 关联：AGENTS.md §7；ROADMAP P2/SEQ-001；docs/requirements/SEQ-001.md

## 背景

运单、调拨单、运输批次等业务单据需要租户内唯一的业务单号；AGENTS §7 禁止 `SELECT MAX(number) + 1`；P0 遗留的单号格式业务规则尚未由业务方最终确认。

## 决策

1. **序号分配**：`branch_sequences` 行级计数表 + `INSERT ... ON CONFLICT ... DO UPDATE ... RETURNING` 单语句原子递增；按（租户、网点、单据类型、期间 yyyyMMdd）维度计数，按日自然重置。
2. **单号格式（建议）**：`{前缀}{网点编码}{yyyyMMdd}{6位序号}`，前缀 `YB`/`DB`/`PC` 对应运单/调拨/批次；格式集中于 `BusinessNumberFormatter`，业务审定后单点变更，分配机制不受影响。
3. **唯一性**：单号在租户内唯一，由运单等业务表的 `(tenant_id, no)` 唯一索引兜底（在引用方任务落地）。
4. **跳号**：事务回滚不回收序号；连续性不保证，唯一性硬保证。
5. **溢出**：序号超过 999999 明确报错，不静默回绕。

## 后果

- 并发分配只产生行级锁冲突，吞吐满足专线场景；
- 网点编码长度影响单号总长（非定长单号），下游若依赖定长需在业务确认时一并审定；
- 溢出扩位需人工迁移（评估实际容量后再定）。

## 依据

AGENTS.md §7（事务安全的序号分配方案、禁止 MAX+1）；ROADMAP P2（并发创建单号不会重复）；会话内建议格式（YB+网点码+yyyyMMdd+6 位序号）待业务方最终审定。
