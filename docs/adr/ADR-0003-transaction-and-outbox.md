# ADR-0003：事务、Outbox 与幂等策略

- 状态：已接受
- 日期：2026-11-17
- 关联：AGENTS.md §4.3、§6.5；ROADMAP §2.3

## 背景

运单、仓储、财务与 COD 涉及大量必须原子完成的业务步骤（开单计价、收款核销、COD 结算等），同时需要跨模块事件通知和后台任务。错误的异步化或重复执行会破坏资金与货物流转的正确性。

## 决策

1. 同一数据库内需要强一致的业务操作使用明确的数据库事务；不得把必须原子完成的业务步骤拆成异步事件。
2. 跨模块可靠事件使用 Outbox 模式：业务数据与待发布事件在同一事务内写入 `outbox_messages`，由后台进程投递。
3. 消费端必须考虑重复投递，处理逻辑具备幂等性；幂等键记录于 Platform 模块 `idempotency_records`。
4. 关键写命令（创建运单、收款、发车、交接、签收、COD 结算等）设计幂等策略；并发更新使用乐观并发控制或明确的数据库锁策略。
5. 财务流水、运单事件、交接记录采用追加式设计；错误通过反向流水、退款或冲正处理，禁止静默修改或删除原记录。
6. 后台任务（Hangfire）必须显式建立租户上下文，不得依赖请求线程中的隐式状态。
7. 不在没有业务规则和审批约束时自动执行真实资金付款。

## 后果

- 每个关键写任务必须回答：事务边界、幂等键、并发冲突处理三件事，并配套集成测试（幂等、并发、Outbox 写入与消费、后台任务租户上下文）。
