# ORG-001：网点、用户、角色和权限模型 — 设计方案

- 状态：已确认（沿用 AGENTS.md 已确认约束；HTTP API 边界见第 2 节）
- 日期：2026-11-17
- 关联：ROADMAP P1/ORG-001；AGENTS.md §4.2、§5.2、§8；ADR-0001、ADR-0005；TEN-001 设计文档

## 1. 业务目标

为一家租户（企业）建立直营网点、员工、角色与权限的领域模型，并**首次落地**租户范围数据隔离的基础设施：

1. `ITenantScopedEntity` 全局查询过滤器（EF Core 纵深防御，非唯一安全边界）。
2. 复合外键 `(tenant_id, entity_id)`，从数据库层阻断跨租户引用。

## 2. 范围

**实现：**

- 领域实体与状态机：`Branch`（网点）、`User`（员工）、`Role`（角色）、`UserRole`、`UserBranchScope`（网点授权）、`RolePermission`、权限点清单。
- EF Core 映射 + 迁移（含数据库层约束与预置权限点）。
- 密码哈希原语（PBKDF2-SHA256，供后续登录任务使用）。
- 集成测试：跨租户复合外键拒绝、全局过滤器租户隔离与 fail-closed、唯一约束、xmin 并发。

**不实现（明确排除）：**

- 登录/刷新令牌/JWT 签发（后续登录任务）。
- 网点/用户/角色的 HTTP CRUD 端点与启停用接口：登录与权限校验未实现前不暴露业务 API（AGENTS §8）。本任务先固化模型与数据层，端点随登录任务交付。
- 前端页面（P1 前端任务）。

## 3. 表结构（全部为租户范围表，实现 ITenantScopedEntity）

通用规则：主键 UUID；`tenant_id uuid NOT NULL`；审计字段 `created_at/created_by/updated_at/updated_by`；`xmin` 乐观并发；标识符 snake_case；租户范围唯一约束必须包含 `tenant_id`（AGENTS §7）。

### branches（直营网点）

```sql
CREATE TABLE branches (
    id uuid PRIMARY KEY,
    tenant_id uuid NOT NULL,
    code varchar(64) NOT NULL,     -- 网点编码，租户内唯一
    name varchar(200) NOT NULL,
    status smallint NOT NULL CHECK (status IN (0, 1)),  -- 0=启用 1=停用
    created_at timestamptz NOT NULL, ... ,
    xmin rowversion
);
CREATE UNIQUE INDEX ux_branches_tenant_code ON branches (tenant_id, code);
CREATE UNIQUE INDEX ux_branches_tenant_id ON branches (tenant_id, id);  -- 复合外键目标
```

### users（员工）

```sql
CREATE TABLE users (
    id uuid PRIMARY KEY,
    tenant_id uuid NOT NULL,
    username varchar(64) NOT NULL,        -- 登录名，租户内唯一
    display_name varchar(200) NOT NULL,
    password_hash text NOT NULL,          -- pbkdf2-sha256$<iterations>$<salt b64>$<hash b64>
    tenant_wide_scope boolean NOT NULL DEFAULT false,  -- 租户级数据范围（服务端显式授予，AGENTS §5.2）
    status smallint NOT NULL CHECK (status IN (0, 1)), -- 0=启用 1=禁用
    created_at timestamptz NOT NULL, ... , xmin rowversion
);
CREATE UNIQUE INDEX ux_users_tenant_username ON users (tenant_id, username);
CREATE UNIQUE INDEX ux_users_tenant_id ON users (tenant_id, id);
```

### roles（角色）

```sql
CREATE TABLE roles (
    id uuid PRIMARY KEY,
    tenant_id uuid NOT NULL,
    code varchar(64) NOT NULL,     -- 租户内唯一
    name varchar(200) NOT NULL,
    status smallint NOT NULL CHECK (status IN (0, 1)),  -- 停用后权限即时失效（P1 验收标准）
    created_at timestamptz NOT NULL, ... , xmin rowversion
);
CREATE UNIQUE INDEX ux_roles_tenant_code ON roles (tenant_id, code);
CREATE UNIQUE INDEX ux_roles_tenant_id ON roles (tenant_id, id);
```

### permissions（权限点，平台全局表，非租户范围）

```sql
CREATE TABLE permissions (
    id uuid PRIMARY KEY,           -- 迁移预置固定 Guid
    code varchar(100) NOT NULL,    -- 如 organization.branch.manage
    name varchar(200) NOT NULL,
    module varchar(64) NOT NULL
);
CREATE UNIQUE INDEX ux_permissions_code ON permissions (code);
```

### 关联表（复合主键，追加式关联，无独立 id）

```sql
CREATE TABLE user_roles (
    tenant_id uuid NOT NULL,
    user_id uuid NOT NULL,
    role_id uuid NOT NULL,
    PRIMARY KEY (tenant_id, user_id, role_id)
);
CREATE TABLE user_branch_scopes (
    tenant_id uuid NOT NULL,
    user_id uuid NOT NULL,
    branch_id uuid NOT NULL,
    PRIMARY KEY (tenant_id, user_id, branch_id)
);
CREATE TABLE role_permissions (
    tenant_id uuid NOT NULL,
    role_id uuid NOT NULL,
    permission_id uuid NOT NULL,
    PRIMARY KEY (tenant_id, role_id, permission_id)
);
```

## 4. 数据库层约束（首次落地复合外键）

**复合外键**（数据库层阻断跨租户引用，AGENTS §5.1）：

| 子表 | 复合外键 | 目标（需唯一索引） |
| --- | --- | --- |
| user_roles | (tenant_id, user_id) | users (tenant_id, id) |
| user_roles | (tenant_id, role_id) | roles (tenant_id, id) |
| user_branch_scopes | (tenant_id, user_id) | users (tenant_id, id) |
| user_branch_scopes | (tenant_id, branch_id) | branches (tenant_id, id) |
| role_permissions | (tenant_id, role_id) | roles (tenant_id, id) |
| branches/users/roles | (tenant_id) | tenants (id) |

EF 模型只配置列与唯一索引；跨模块外键（→ tenants）与复合外键通过迁移中的 `migrationBuilder.AddForeignKey` 显式添加（Organization 模块不引用 Tenancy 领域实体，保持模块边界；约束集中在 Initial 迁移，可在空库执行）。

**EF Core 全局查询过滤器**：`OrganizationDbContext` 为所有 `ITenantScopedEntity` 统一配置
`e => e.TenantId == tenantContext.TenantId`；上下文无租户时表达式恒为 false → **fail-closed**（查不到任何行）。过滤器只是纵深防御，真实授权在服务端逐次校验（后续任务）。

## 5. 权限点清单（预置 seed）

模块内权限点采用 `模块.资源.动作` 命名，首期只预置组织域：

- `organization.branch.read` / `organization.branch.manage`（创建、编辑、启停用）
- `organization.user.read` / `organization.user.manage`
- `organization.role.read` / `organization.role.manage`

后续模块（客户、运单、财务…）在各自任务中追加权限点。

## 6. 密码哈希（SharedKernel 通用原语）

- PBKDF2-HMACSHA256，100,000 次迭代，128-bit 随机盐，256-bit 派生密钥。
- 存储格式：`pbkdf2-sha256$100000$<salt-b64>$<hash-b64>`；验证采用固定时间比较。

## 7. 测试计划

### 单元测试

- `Branch`/`User`/`Role`：创建校验（空码/空名）、启停用幂等、UTC 校验。
- `PasswordHasher`：哈希可验证、错误密码拒绝、相同口令两次哈希产生不同盐、格式可解析。

### 集成测试（Testcontainers PostgreSQL 17）

1. 迁移可在空库执行（含权限点 seed）。
2. **租户范围唯一约束**：租户 A 与租户 B 可各自拥有相同网点编码；同租户重复编码被唯一索引拒绝。
3. **跨租户复合外键拒绝（首次落地证据）**：向 `user_branch_scopes` 插入 (租户 A, 租户 B 的网点) → FK 违反。
4. **全局查询过滤器隔离**：租户 A、B 各有网点；上下文租户 A → 只查到 A 的网点；上下文 B → 只查到 B 的网点；**上下文为空 → 返回 0 行（fail-closed）**。
5. **xmin 乐观并发**：两个上下文更新同一网点 → 第二次保存抛 `DbUpdateConcurrencyException`。
6. 关联表复合主键幂等：重复插入相同 (tenant_id, user_id, branch_id) 被拒绝。

### 暂缓（如实说明）

- HTTP 端点级越权测试（401/403）：随登录与权限校验任务补齐。
- 禁用用户/网点/角色后权限即时生效的行为测试：依赖权限校验器（ORG-002 与登录任务）。

## 8. 验收标准

- [ ] 迁移可在空数据库执行。
- [ ] 租户 A 无法通过 EF 查询读到租户 B 的网点/用户/角色数据；无租户上下文时一律 0 行。
- [ ] 数据库层拒绝跨租户引用（复合外键）。
- [ ] 一个用户可被授权多个网点（`user_branch_scopes` 多行）。
- [ ] 上述测试全部通过。
