# CUS-001：客户、联系人、地址和网点授权 — 设计方案

- 状态：已确认（沿用 AGENTS.md/ROADMAP.md 已确认约束）
- 日期：2026-11-17
- 关联：ROADMAP P2/CUS-001；AGENTS.md §5、§7；ADR-0001；ORG-001/ORG-002 设计文档

## 1. 业务目标

完成开单前所需的客户主数据：客户档案、联系人、地址，以及"一个客户可授权多个直营网点服务"的关系（P2 验收标准）。

## 2. 范围

**实现：**

1. 领域模型：`Customer`、`CustomerContact`、`CustomerAddress`、`CustomerBranchRelation`。
2. EF Core 映射 + `InitialCustomers` 迁移（复合外键 + 部分唯一索引）。
3. `CustomerRelationshipService`：客户-网点服务关系的授权/收回（幂等）与双向查询。
4. 单元测试 + 集成测试（越权、隔离、幂等、并发）。

**不实现（明确排除）：**

- 客户/联系人/地址的 HTTP CRUD 端点（登录与权限校验任务交付）；
- 客户物理删除（未确认删除规则；停用用 `status` 表达，历史引用安全）；
- 省市区结构化地址模型（ROADMAP 未确认编码规则，地址以完整文本存储，后续确认后可扩展）；
- 客户信用/账期字段（属 P7 月结任务）。

## 3. 表结构（全部为租户范围表，实现 ITenantScopedEntity）

### customers（客户档案）

```sql
CREATE TABLE customers (
    id uuid PRIMARY KEY,
    tenant_id uuid NOT NULL,
    code varchar(64) NOT NULL,      -- 客户编码，租户内唯一
    name varchar(200) NOT NULL,
    remark varchar(500) NULL,
    status smallint NOT NULL CHECK (status IN (0, 1)),  -- 0=启用 1=停用
    created_at timestamptz NOT NULL, created_by uuid NULL,
    updated_at timestamptz NULL,    updated_by uuid NULL,
    xmin rowversion
);
CREATE UNIQUE INDEX ux_customers_tenant_code ON customers (tenant_id, code);
CREATE UNIQUE INDEX ux_customers_tenant_id ON customers (tenant_id, id);  -- 复合外键目标
```

### customer_contacts（联系人）

```sql
CREATE TABLE customer_contacts (
    id uuid PRIMARY KEY,
    tenant_id uuid NOT NULL,
    customer_id uuid NOT NULL,      -- 复合外键 (tenant_id, customer_id) → customers(tenant_id, id)
    name varchar(100) NOT NULL,
    phone varchar(50) NOT NULL,     -- 物流业务核心联系方式
    is_primary boolean NOT NULL DEFAULT false,  -- 主联系人
    remark varchar(500) NULL,
    created_at timestamptz NOT NULL, ... , xmin rowversion
);
CREATE UNIQUE INDEX ux_customer_contacts_tenant_customer_primary
    ON customer_contacts (tenant_id, customer_id) WHERE is_primary;  -- 部分唯一索引：每客户至多一个主联系人
```

### customer_addresses（地址）

```sql
CREATE TABLE customer_addresses (
    id uuid PRIMARY KEY,
    tenant_id uuid NOT NULL,
    customer_id uuid NOT NULL,      -- 复合外键
    label varchar(100) NULL,        -- 地址用途（如"仓库"、"门店"），可选
    address varchar(500) NOT NULL,  -- 完整地址文本
    is_default boolean NOT NULL DEFAULT false,
    remark varchar(500) NULL,
    created_at timestamptz NOT NULL, ... , xmin rowversion
);
CREATE UNIQUE INDEX ux_customer_addresses_tenant_customer_default
    ON customer_addresses (tenant_id, customer_id) WHERE is_default;
```

### customer_branch_relations（客户-网点服务关系，关联表）

```sql
CREATE TABLE customer_branch_relations (
    tenant_id uuid NOT NULL,
    customer_id uuid NOT NULL,
    branch_id uuid NOT NULL,
    created_at timestamptz NOT NULL, created_by uuid NULL,
    PRIMARY KEY (tenant_id, customer_id, branch_id)
);
```

关联表追加 `created_at/created_by`（记录授权发生时间与操作者，审计明细随 Platform `audit_logs` 任务完善）。

## 4. 数据库层约束

**复合外键**（复用 ORG-001 建立的模式：EF 模型只配列与唯一索引，外键在迁移中用 `migrationBuilder.AddForeignKey` 显式添加）：

| 子表 | 复合外键 | 目标 |
| --- | --- | --- |
| customer_contacts / customer_addresses / customer_branch_relations | (tenant_id, customer_id) | customers (tenant_id, id) |
| customer_branch_relations | (tenant_id, branch_id) | **branches** (tenant_id, id)（ORG-001 已建唯一索引）——跨模块纯数据库引用，Customers 模块不引用 Organization 领域实体 |
| customers | (tenant_id) | tenants (id) |

**部分唯一索引**（PostgreSQL `WHERE`）：每客户至多一个主联系人、至多一个默认地址——数据层防线，切换主联系人/默认地址的业务流（先清旧再设新）随 CRUD 任务实现。

## 5. 全局查询过滤器复用

`CustomersDbContext` 复制 Organization 模块的约定实现：所有 `ITenantScopedEntity` 统一配置
`e.TenantId == this.TenantId`（引用 DbContext 实例属性，编译时按当前上下文求值，模型缓存安全）；
无租户上下文 → 0 行（fail-closed）。

## 6. CustomerRelationshipService（客户-网点授权）

- `GrantBranchServiceAsync(customerId, branchId)` / `RevokeBranchServiceAsync`：幂等；客户与网点必须同租户（过滤器保证查不到即 `EntityNotFoundException`）。
- `GetServicedBranchIdsAsync(customerId)`：客户被授权的网点。
- 写入顺序约定（ORG-001 经验）：先确认主体存在，再写关联表（关联表与主体无导航关系，不保证同批插入顺序）。

## 7. 测试计划

### 单元测试

- `Customer.Create` 校验：空/超长 code、name；启用初始状态；Disable/Enable 幂等。
- `CustomerContact.Create`：主联系人标记；空 name/phone 拒绝。
- `CustomerAddress.Create`：空 address 拒绝；默认地址标记。

### 集成测试（Testcontainers）

1. 迁移可在空库执行。
2. 租户范围唯一：跨租户同客户编码允许；同租户重复被拒。
3. **跨租户复合外键拒绝**：联系人/地址引用其他租户客户 → FK 违反；客户-网点关系引用其他租户网点 → FK 违反。
4. **全局过滤器隔离**：租户 A/B 各建客户，各自只能查到自己的；无租户上下文 → 0 行（fail-closed）。
5. 部分唯一索引：同客户两个主联系人 → 违反；两个默认地址 → 违反。
6. `CustomerRelationshipService`：授权/收回幂等；被授权网点列表；对他租户网点授权抛 `EntityNotFoundException`。
7. xmin 乐观并发：两个上下文更新同一客户 → 第二次抛 `DbUpdateConcurrencyException`。

## 8. 验收标准

- [ ] 一个客户可授权多个直营网点服务。
- [ ] 一个网点可服务多个客户（关系表多行）。
- [ ] 客户数据按租户隔离（过滤器 + 复合外键 + 租户范围唯一约束）。
- [ ] 上述测试全部通过。
