# SEQ-001：网点业务单号生成 — 设计方案

- 状态：已确认（单号格式为**建议格式**，集中封装于 `BusinessNumberFormatter`，审定后单点可改）
- 日期：2026-11-17
- 关联：ROADMAP P2/SEQ-001、P0 单号规则任务；AGENTS.md §7（禁止 `SELECT MAX+1`）；ADR-0006

## 1. 业务目标

为运单、调拨单、运输批次等业务单据提供**事务安全、并发唯一、按网点按日递增**的业务单号生成能力（P2 验收：并发创建单号不会重复）。

## 2. 分配机制（禁止 SELECT MAX+1）

**方案：行级计数表 + 单语句原子递增**（`branch_sequences`，ROADMAP §3 归属 Platform 模块）：

```sql
INSERT INTO branch_sequences (tenant_id, branch_id, doc_type, period, current_value, updated_at)
VALUES (@tenant, @branch, @docType, @period, 1, now())
ON CONFLICT (tenant_id, branch_id, doc_type, period)
DO UPDATE SET current_value = branch_sequences.current_value + 1, updated_at = now()
RETURNING current_value;
```

- 单条 SQL 完成"不存在则初始化为 1 / 存在则 +1"，行锁保证并发下原子且无重复；
- 期间（period，如 `20261117`）变化时自然重置为 1（按日重置）；
- 应用层不做"读-改-写"，无竞态窗口；
- 无显式表锁，高并发下仅行级锁冲突。

**跳号说明**：业务事务回滚时已分配的序号不回收（跳号），唯一性是硬约束、连续性不作保证——专线物流行业惯例，写入文档。

## 3. 表结构

```sql
CREATE TABLE branch_sequences (
    tenant_id uuid NOT NULL,
    branch_id uuid NOT NULL,
    doc_type smallint NOT NULL,       -- 1=运单 2=调拨单 3=运输批次（BusinessDocumentType）
    period varchar(8) NOT NULL,       -- 归属期间 yyyyMMdd（按日重置）
    current_value bigint NOT NULL DEFAULT 0 CHECK (current_value >= 0),
    updated_at timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (tenant_id, branch_id, doc_type, period)
);
-- 复合外键：网点必须属于本租户（branches(tenant_id, id)，ORG-001 已建唯一索引）
```

## 4. 单号格式（建议格式，供审定）

```text
{前缀}{网点编码}{yyyyMMdd}{6位序号}
YB  + GZ01 + 20261117 + 000001  →  YBGZ0120261117000001   （运单）
DB  + GZ01 + 20261117 + 000001  →  DBGZ0120261117000001   （调拨单）
PC  + GZ01 + 20261117 + 000001  →  PCGZ0120261117000001   （运输批次）
```

- 前缀建议：`YB`=运单、`DB`=调拨、`PC`=批次（拼音缩写，符合国内专线习惯；审定可改）；
- 唯一性论证：租户内网点编码唯一（`(tenant_id, code)`）+ 同网点同日序号递增 → 单号在租户内唯一；
- 容量：6 位序号 = 单网点单日上限 999,999 票；**溢出明确报错**（不静默回绕），扩位需人工评估后迁移；
- 格式集中封装于 `BusinessNumberFormatter`（纯函数），审定变更只改一处。

> ⚠️ 本格式为建议值。若业务确认需要其他规则（如全大写网点码、流水线位数不同、加校验位），修改 `BusinessNumberFormatter` + 对应测试即可，分配机制不受影响。

## 5. 实现

- `BusinessDocumentType`（Domain 枚举）：Waybill=1、BranchTransfer=2、TransportTrip=3；新单据类型加枚举值即可。
- `BranchSequenceService`（Application，scoped）：`NextNumberAsync(branchId, docType, date, branchCode)`；无租户上下文 → 拒绝（fail-closed）。
- `PlatformDbContext`：`branch_sequences` 实现 `ITenantScopedEntity`（复合主键含 tenant_id），复用全局过滤器约定；原生 SQL 分配语句显式携带租户参数（不依赖过滤器兜底，AGENTS §5.1）。
- 组合根注册 + `InitialPlatform` 迁移。

## 6. 测试计划

### 单元测试（BusinessNumberFormatter）

- 三种单据类型前缀映射；6 位补零；溢出（999999+1）抛出明确异常；期间格式化。

### 集成测试（Testcontainers）

1. 迁移可在空库执行。
2. **并发唯一性（核心）**：20 个并发任务（各自 DbContext）分配运单号 → 无重复且序号恰为 1..20。
3. 按日重置：同网点不同日期各自从 1 开始。
4. 跨网点独立：同租户不同网点各自从 1 开始。
5. 跨租户独立：不同租户同网点序号各自独立（各租户计数行隔离）。
6. 单号格式正确（前缀+网点码+期间+6 位序号）。
7. 无租户上下文分配 → 拒绝（fail-closed）。
