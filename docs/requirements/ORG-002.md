# ORG-002：多网点数据范围授权与权限校验器 — 设计方案

- 状态：已确认（沿用 AGENTS.md §5.2 已确认约束）
- 日期：2026-11-17
- 关联：ROADMAP P1/ORG-002；AGENTS.md §5.2、§8；ADR-0001、ADR-0005；ORG-001 设计文档

## 1. 业务目标

实现"角色权限 × 网点数据范围"的组合授权：员工只能访问被授权的网点；禁用用户、网点或角色后权限**即时**按规则生效（P1 验收标准）。

## 2. 范围

**实现：**

1. `IAuthorizationService`（Organization 模块 Application）：
   - 授权变更命令：`AssignRoleAsync` / `RemoveRoleAsync` / `GrantBranchScopeAsync` / `RevokeBranchScopeAsync` / `GrantPermissionAsync` / `RevokePermissionAsync`；
   - 校验查询：`HasPermissionAsync` / `GetAuthorizedBranchIdsAsync` / `CanAccessBranchAsync` / `AuthorizeAsync`（组合判断）。
2. `PermissionEvaluator`：纯函数聚合规则（内存可测，无 EF 依赖）。
3. 依赖注入注册（scoped）。
4. 集成测试覆盖"禁用即时生效"等行为。

**不实现（明确排除）：**

- HTTP 端点（登录/认证未实现，随登录任务交付）；
- 权限/授权缓存（当前每次校验实时查库，保证即时生效；Redis 缓存如有性能需要再引入并重新评估失效策略）；
- 审计日志（授权变更的审计随 Platform `audit_logs` 任务接入，本任务保证行为正确）；
- JWT claim 组装（登录任务）。

## 3. 组合授权规则

**有效权限（功能权限）**：

```text
effectivePermissions(userId) = ⋃ permissions(role)   仅取 status = 启用 的角色
user.status = 禁用  →  无任何权限
```

**有效网点范围（数据范围）**：

```text
user.tenant_wide_scope = true   →  本租户内全部【启用】网点
否则                            →  user_branch_scopes 中【启用】网点的交集
user.status = 禁用  →  空范围
```

**组合判断**：

```text
Authorize(userId, branchId, permissionCode)
    = HasPermission(userId, permissionCode)
      ∧ CanAccessBranch(userId, branchId)
CanAccessBranch = branch 属于本租户 ∧ branch 启用 ∧ branchId ∈ 有效网点范围
```

要点（全部来自已确认约束）：

- 角色权限与网点数据范围分开建模（AGENTS §5.2）：一个角色可以分配给多个用户；一个用户可有多个角色；一个用户可被授权多个网点（一行一个网点）。
- 租户级范围必须由服务端显式授予（`users.tenant_wide_scope`），不因"没有网点授权记录"而隐式获得全部网点。
- 停用网点从有效范围移除，但授权记录保留（重新启用即恢复）——与"禁用网点后权限即时生效"一致。
- **即时生效靠无缓存实时查询**：校验直接读当前数据库状态，禁用操作提交后下一次校验即生效。

## 4. 租户与越权防护

- 校验器所有查询经 `OrganizationDbContext`（全局查询过滤器，TEN/ORG-001 已落地）。
- `userId` 不属于当前租户 → 用户查不到 → 一律拒绝（fail-closed）。
- 授权变更命令对目标实体做存在性检查：跨租户引用在应用层即拒绝（数据库复合外键是最后防线）。
- 关联表无导航关系（ORG-001），授权写入顺序：确认主体存在 → 写关联表（独立 SaveChanges）。

## 5. 依赖与实现要点

- `AuthorizationService`（scoped）注入 `OrganizationDbContext`（自带租户上下文）。
- 查询聚合避免笛卡尔积：权限点用 `user_roles join roles join role_permissions join permissions` 过滤启用状态；网点范围用 `users → scopes → branches`。
- 异常：目标实体不存在/跨租户 → `EntityNotFoundException`（Application 通用异常，后续 API 任务映射 404）。
- 幂等：关联写入前查存在性，已存在则 no-op（复合主键数据库层兜底）。

## 6. 测试计划

### 单元测试（PermissionEvaluator 纯函数）

- 启用角色权限并集；禁用角色权限被排除；空角色 → 空权限。
- 租户级范围 → 传入的启用网点全集；行级范围 → scopes ∩ 启用网点（停用网点被排除）；禁用用户 → 空。

### 集成测试（Testcontainers，行为级）

1. 用户被授权多个网点 → `GetAuthorizedBranchIds` 返回全部；`tenant_wide_scope` → 返回本租户全部启用网点（不含其他租户）。
2. 组合授权矩阵：有权限+有范围 → true；有权限+无范围 → false；无权限+有范围 → false；停用网点 → false。
3. **禁用角色 → 权限即时失效**（重新启用恢复）。
4. **禁用用户 → 权限与范围全部失效**。
5. **停用网点 → 移出有效范围；重新启用恢复授权**。
6. 授权变更：Grant 后生效、Revoke 后失效；重复 Grant 幂等（不抛错、不产生重复行）。
7. 租户隔离：租户 A 的用户校验租户 B 的网点 → false；租户 B 的角色权限不影响租户 A 用户。

## 7. 验收标准

- [ ] 员工只能访问被授权的网点（含租户级范围显式授予）。
- [ ] 禁用用户、网点或角色后，下一次校验即按规则生效（无缓存延迟）。
- [ ] 一个用户可被授权多个网点。
- [ ] 越权（跨租户/未授权网点/无权限点）一律拒绝。
- [ ] 上述测试全部通过。
